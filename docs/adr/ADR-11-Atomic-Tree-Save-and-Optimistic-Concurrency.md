# ADR 11: Atomic Tree Save and Optimistic Concurrency

**Status**: Proposed

**Date**: 2026-10-26

**Author**: Anderson Arruda

## Context

Phase 1 exposes node-by-node operations (create block, add widget instance,
reorder). An editor works on the whole page in memory and saves it in one
go, like Elementor does. Saving node by node from an editor is slow, can
leave a page half-saved on failure, and lets two editors overwrite each
other. On MongoDB, where every block write rewrites the page's `blocks`
array, concurrent writes can silently lose changes.

## Decision

- Add `saveTree(pageId, tree, expectedVersion)` to the page/block API. It
  **replaces the whole working tree atomically**: either the full tree is
  stored, or nothing changes.
- Every page has a `tree_version` integer, incremented by every write to its
  working tree (including the node-by-node operations, which remain for
  programmatic use).
- `saveTree` succeeds only if the stored `tree_version` equals
  `expectedVersion`; otherwise it throws a conflict error (HTTP 409 in the
  API) and the editor reloads or merges.
- **Node ids are ULIDs on both drivers**, generated by the client for new
  nodes. Ids stay stable across saves, so the editor's selection, revisions
  and diffs can refer to the same node over time.
- SQL: one transaction that checks and bumps `tree_version`, then upserts
  changed nodes and deletes missing ones. MongoDB: one conditional update of
  the page document matching `tree_version`, which is atomic on a single
  document without transactions.

## Consequences

**Positive**:
- No half-saved pages and no silent lost updates on either driver.
- One request per save from the editor.
- Same id format on both drivers, which the canonical tree (ADR 12) needs.

**Negative**:
- SQL block and widget instance ids change from auto-increment integers to
  ULID strings (a schema change to Phase 1).
- Two people editing the same page get a conflict instead of a merge.

**Mitigation**:
- The schema change lands before the first release (pre-release migration
  policy, ADR 13).
- Conflicts show who saved and when; real-time co-editing can be added later
  on top of the same version check.

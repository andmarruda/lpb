# Laravel Page Builder 0.1.0-beta.1 — "Kessel Run"

> Made the Kessel Run in less than twelve parsecs: pages published in one
> click and served from a cache that never goes stale.

**Laravel Page Builder (LPB)** is the backend of a visual page builder for
Laravel. Laravel is the source of truth: it validates, stores, versions and
serves every page. The page itself is mounted by your frontend framework —
React, Vue, Svelte or Angular — through the companion `lpb-frontend`
packages. Store pages in **SQL** (MySQL, PostgreSQL, SQLite) or **MongoDB**,
deliver them through **Inertia**, a **Blade shell** or a **headless API**.

This is the first open beta. The API and the canonical page format are
stable enough to build on; database migrations may still change until
`v0.1.0` (ADR 13).

## What it does

### One page format for every frontend
Every page is a single, versioned JSON document (`format_version` 1),
identical for both databases: nested `flex` and `grid` blocks, each holding
its widgets and child blocks, with ULID ids, per-node styles and the page's
SEO and metatags. Frontends receive it ready to render.

### 48 built-in widgets
Heading, text, image, button, divider, spacer, icon, video, audio, map,
alert, star rating, counter, progress bar, icon box, image box, icon list,
testimonial, tabs, accordion, toggle, social icons, gallery, image
carousel, media carousel, video playlist, slides, testimonial carousel,
anchor, call to action, price table, price list, flip box, countdown,
animated headline, blockquote, share buttons, nav menu, table of contents,
progress tracker, off-canvas, search form, form, author box, code
highlight, hotspot, text path — and a raw HTML widget that is off unless
you trust every editor.

### Your own widgets, validated
A widget is one PHP class with a fluent schema (`string`, `media`, `link`,
`richText`, `array`, `enum`, …) that becomes JSON Schema 2020-12. Every
config is validated on every write; errors come back as JSON pointers
(`/blocks/0/widgets/1/config/title`) so the editor can mark the field.
Change a widget's shape, add an `upgrade()` step and old pages keep working.
`php artisan lpb:make-widget Hero --frameworks=react,vue` scaffolds the PHP
definition and the components; `lpb:types` writes the TypeScript types.

### Safe editing
The whole tree is saved atomically with optimistic concurrency: if two
editors save the same page, one wins and the other gets a `409` with the
current version instead of silently losing work. Depth and size limits keep
trees sane.

### Draft, publish, roll back
Editors work on a draft; visitors only ever see a published snapshot.
Publishing creates a revision (the last three are kept), rollback serves an
older one in a click, and any revision can be restored into the draft.
Unpublish, archive and unarchive complete the lifecycle.

### A cache that never goes stale
Published payloads are cached by revision and design version, so they never
need invalidating: publishing only moves a short pointer. Template changes,
media replacements and `php artisan lpb:design:bump` roll every page to new
cache keys at once. External frontends get signed (HMAC-SHA256), queued,
retried webhooks to revalidate their own caches.

### Media where you want it
Upload images, video and audio to any Laravel disk — local, Amazon S3,
Cloudflare R2 or any S3-compatible bucket — or keep them in the database
itself, served by the package with `nosniff` and a sandboxing CSP. Replace a
file and every page using it shows the new one. Types are detected from the
file contents, never from the name.

### Ready-made HTTP API
A public delivery API (pages with ETags, menus, signed preview links) and an
editor API (pages, tree, publishing, revisions, templates, menus, media)
documented in `docs/openapi.yaml`, protected by your middleware and two
Gates (`lpb.edit`, `lpb.publish`) that deny until you grant them.

### Three ways to boot a page
- **Inertia**: `return Lpb::inertia('home');` — the template's view is the
  root view, the payload is a prop, Inertia SSR works as usual.
- **Blade shell**: `return Lpb::view('home');` — the `<head>` (title, SEO,
  canonical, metatags) is rendered on the server and the framework mounts the
  page from the embedded payload. Works for Angular too.
- **Headless**: Next, Nuxt, SvelteKit or Angular SSR call the delivery API
  and listen to the webhooks.

## Security
- Gates deny editing and publishing until the application defines them.
- Widget configs and styles are validated before they are stored; style
  values cannot break out of their CSS declaration; `$dynamic` references
  are rejected until specified.
- Rich text is sanitised by the renderers with an allowlist; links and media
  URLs must be http(s), mailto, tel or relative; the raw HTML widget is
  opt-in.
- Uploads: content-detected types, size limit, generated file names, SVG
  off by default.
- Signed, expiring preview URLs; signed webhooks.

## Quality
- Shared test scenarios run identically on SQLite, MySQL 8.4 and MongoDB 7,
  on PHP 8.2 (Laravel 12) and PHP 8.3 (Laravel 13): ~300 tests per database.
- The frontend's end-to-end suite renders every widget in React, Vue,
  Svelte and Angular against a real Laravel app, exercises the editor API
  and checks that stored script payloads never run.

## Requirements
PHP 8.2+, Laravel 10–13. MongoDB needs `mongodb/laravel-mongodb` ^5;
Inertia needs `inertiajs/inertia-laravel`; S3 and R2 need
`league/flysystem-aws-s3-v3`.

## Install
```bash
composer require andmarruda/lpb
php artisan vendor:publish --tag=lpb-config
php artisan vendor:publish --tag=lpb-migrations-sql && php artisan migrate   # SQL
php artisan lpb:install-mongo                                                # MongoDB
```

## Known limits of this beta
- The visual editor UI is not part of this release; its building blocks (the
  editor API, `TreeStore` and `LpbClient` in `@lpb/core`) are.
- Dynamic content (posts, loops, logins) waits for `$dynamic` references.
- One site and one locale for now; cache keys already carry both.

# Laravel Page Builder 0.1.0-beta.1 — "Kessel Run"

> Fez a Kessel Run em menos de doze parsecs: páginas publicadas com um clique
> e servidas por um cache que nunca fica desatualizado.

O **Laravel Page Builder (LPB)** é o backend de um construtor visual de
páginas para Laravel. O Laravel é a fonte da verdade: valida, armazena,
versiona e entrega cada página. A página em si é montada pelo seu framework
de frontend — React, Vue, Svelte ou Angular — pelos pacotes do
`lpb-frontend`. As páginas ficam em **SQL** (MySQL, PostgreSQL, SQLite) ou
**MongoDB** e são entregues por **Inertia**, por um **shell Blade** ou por uma
**API headless**.

Esta é a primeira beta aberta. A API e o formato da página já são estáveis
para construir em cima; as migrations ainda podem mudar até a `v0.1.0`.

## O que ele faz

- **Um formato de página para todos os frontends**: um único JSON
  versionado, igual nos dois bancos — blocos `flex` e `grid` aninhados, com
  widgets, filhos, IDs ULID, estilos por nó e o SEO da página.
- **48 widgets prontos**: título, texto, imagem, botão, vídeo, áudio, mapa,
  abas, acordeão, toggle, galeria, carrosséis (imagem, mídia, depoimentos),
  playlist de vídeo, slides, tabela e lista de preços, flip box, contagem
  regressiva, título animado, botões de compartilhar, menu, índice, barra de
  leitura, off-canvas, busca, formulário, caixa de autor, código, hotspot,
  texto em curva e mais — o widget de HTML puro fica desligado por padrão.
- **Seus próprios widgets, validados**: uma classe PHP com schema fluente
  vira JSON Schema 2020-12; toda configuração é validada a cada gravação, com
  erros apontando o campo exato. Mudou o formato? Um passo `upgrade()` e as
  páginas antigas continuam funcionando. `lpb:make-widget` gera a classe e
  os componentes; `lpb:types` gera os tipos TypeScript.
- **Edição segura**: a árvore inteira é salva de forma atômica; se dois
  editores salvarem a mesma página, um vence e o outro recebe um `409` em vez
  de perder trabalho em silêncio.
- **Rascunho, publicação e rollback**: visitantes só veem a versão
  publicada; cada publicação vira uma revisão (as três últimas ficam
  guardadas), o rollback é um clique e qualquer revisão pode voltar para o
  rascunho.
- **Cache que nunca fica velho**: o conteúdo publicado é cacheado por
  revisão; publicar só move um ponteiro. Trocar template ou mídia renova
  tudo de uma vez. Frontends externos recebem webhooks assinados.
- **Mídia onde você quiser**: upload de imagens, vídeos e áudios para disco
  local, Amazon S3, Cloudflare R2 ou qualquer bucket compatível com S3 — ou
  no próprio banco de dados. Substituiu o arquivo, todas as páginas mostram o
  novo. O tipo é detectado pelo conteúdo, nunca pelo nome.
- **API HTTP pronta**: entrega pública (páginas com ETag, menus, preview
  assinado) e API do editor (páginas, árvore, publicação, revisões,
  templates, menus, mídia), documentadas em OpenAPI e protegidas por Gates
  que negam até você liberar.
- **Três formas de abrir a página**: Inertia (`Lpb::inertia`), shell Blade
  com o `<head>` renderizado no servidor (`Lpb::view`) ou headless (Next,
  Nuxt, SvelteKit, Angular SSR).

## Segurança
Gates negando por padrão, validação de tudo antes de gravar, estilos que não
escapam da declaração CSS, rich text sanitizado com allowlist, URLs só
http(s)/mailto/tel/relativas, uploads com tipo detectado pelo conteúdo e SVG
desligado, links de preview assinados com validade, webhooks assinados.

## Qualidade
Os mesmos cenários de teste rodam em SQLite, MySQL e MongoDB, em PHP 8.2
(Laravel 12) e 8.3 (Laravel 13) — cerca de 300 testes por banco. A suíte
end-to-end do frontend renderiza todos os widgets em React, Vue, Svelte e
Angular contra um Laravel real e confirma que scripts gravados nunca rodam.

## Limites desta beta
O editor visual ainda não faz parte desta versão (a API e as peças em que
ele se apoia, sim); conteúdo dinâmico (posts, loops, login) espera as
referências `$dynamic`; por enquanto um site e um idioma.
